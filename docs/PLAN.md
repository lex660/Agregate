# Этап 2. Цель MVP и дорожная карта

Дата: 12.10.2026.

## Цель MVP

Человек из Ингушетии, Дагестана или Чечни заходит на сайт с телефона, вводит стоимость
покупки, взнос и срок — и за несколько секунд видит, сколько он заплатит в месяц у каждой
компании своего региона, какая наценка, и у кого выгоднее. У каждой цифры указано, откуда
она взята и когда проверена. Компания, которая условия не публикует, показывается честно —
с пометкой, а не с выдуманной ставкой.

Со стороны владельца: сайт работает на своём домене по HTTPS, обновляется сам при
изменении данных в репозитории, а если на сайте компании поменялись цифры — владелец
получает об этом сообщение в Telegram. Разворачивание и поддержка не требуют
программирования.

### Критерии готовности MVP

| Критерий | Проверяется |
|---|---|
| Сайт открывается по своему домену с HTTPS | Вручную + мониторинг |
| Калькулятор считает верно у всех компаний с подтверждёнными ставками | 26 тестов в CI |
| Ни одна цифра не показана без `source` и `verified_at` | `check-site.mjs` в CI |
| Неподходящий тариф не выдаётся за доступный | Тесты на лимиты |
| Мобильная версия: карточки, без горизонтальной прокрутки | Проверка в браузере |
| Core Web Vitals в зелёной зоне | Lighthouse |
| WCAG 2.2 AA по проверенным критериям | Аудит + скилл `wcag-contrast` |
| Аналитика только после согласия, есть политика ПД | Проверка вручную |
| Реклама либо с erid и рекламодателем, либо выключена | `activeAds` + ревью |
| Деплой из `main` проходит без ручных шагов | Успешный прогон workflow |
| Владелец развернул проект по `DEPLOY.md` без вопросов | Финальная приёмка |

### Что сознательно НЕ входит в MVP

- Формы заявки и сбор персональных данных. Это сразу поднимает требования 152-ФЗ,
  а ценность сайта от этого не растёт: заявки оформляются на сайте компании.
- Личный кабинет, регистрация, сохранение расчётов.
- Автоматическое обновление тарифов без участия человека. Сверка присылает уведомление,
  правку вносит человек через PR — осознанное решение, см. `docs/RESEARCH.md`, раздел 2.4.
- Новые регионы за пределами трёх текущих.
- Монетизация. Переход к партнёрским выплатам меняет юридический статус ссылок
  (становятся рекламой, нужен erid) — это отдельный этап после MVP.

## Дорожная карта

### Milestone 1. Сайт снова работает (срочно)

Цель: убрать блокер недоступности и вернуть сайту адрес. Самостоятельная ценность —
даже до всех улучшений сайт станет открываться.

- Влить PR #1 (`rebuild-eleventy`) в `main`
- Убрать `CNAME` на мёртвый домен, перевести Pages на публикацию из GitHub Actions
- Включить принудительный HTTPS
- Решение по домену (владелец, **крайний срок 27.10.2026** — см. ADR-001)
- Удалить старый Cloudflare Worker (владелец)

### Milestone 2. Юридический минимум

Цель: сайт не нарушает 152-ФЗ и закон о рекламе. Блокирует публичный запуск.

- Cookie-баннер с равноценными кнопками «Принять» / «Отклонить»
- Метрика загружается только после согласия, `webvisor` выключен (ADR-004)
- Страница политики обработки персональных данных
- Переименование сайта (ADR-005)
- Проверка: ни один баннер не показывается без `advertiser` и `erid`

### Milestone 3. Данные: полнота и доверие

Цель: закрыть пробелы, из-за которых сайт пока нельзя монетизировать и которые
снижают доверие.

- Заполнить `cbr_registry` по реестру Банка России для компаний Чечни и Дагестана
- Показать статус в реестре ЦБ в карточке предложения
- Объяснить на сайте разницу: Чечня и Дагестан — в эксперименте 417-ФЗ, Ингушетия — нет
- Дозапросить юрлицо и ИНН у компаний, где их нет (5 из 10 без юрлица, 8 без ИНН)
- Получить ставки у 4 компаний со статусом `pending` (ФинЛайт, Khalim, FinHub, Safra)
- Добавить найденные компании: АЛИФ, AMANAT, Т-Банк

### Milestone 4. Качество: скорость, доступность, SEO

- Перевести баннеры из PNG в WebP/AVIF (~600 КБ → десятки КБ)
- Аудит WCAG 2.2 AA: критерии 2.5.7 (ползунок срока) и 2.5.8 (размер целей нажатия)
- Проверка контраста палитры (скилл `wcag-contrast`)
- Разметка `schema.org`: `Organization`, `FinancialProduct`/`Offer`, `FAQPage`, `BreadcrumbList`
- Lighthouse: LCP ≤ 2,5 с, INP ≤ 200 мс, CLS ≤ 0,1
- Проверка мобильной версии на реальной ширине экрана
- Включить Dependabot и secret scanning

### Milestone 5. Пакет для деплоя

Цель: владельцу остаётся оплатить хостинг и пройти по инструкции.

- Вынести S3-endpoint и регион в переменные репозитория (ADR-002)
- `DEPLOY.md`: пошагово для Yandex Object Storage, кратко для Timeweb Cloud,
  на простом русском, с ориентирами «раздел → кнопка», ценой и настройкой DNS
- `.env.example` с описанием каждой переменной
- Настроить и описать Cloud Function сверки тарифов (Telegram-уведомления)
- Мониторинг доступности сайта
- Проверить, что деплой выключен, пока владелец не добавил секреты

### Milestone 6. Публикация

- `README.md`, `CHANGELOG.md`, `LICENSE` (нужен выбор владельца), `.editorconfig`
- Убрать мусор: `index_old.html`, `.DS_Store`
- Релиз `v1.0.0`
- Новый адрес в Яндекс.Вебмастер и Google Search Console, загрузка sitemap
- Независимая проверка: сборка с нуля по README, полнота `DEPLOY.md`
- Итоговый отчёт и чеклист владельца (не более 10 пунктов)

## Что блокирует работу и ждёт владельца

| Что | Зачем | Срок |
|---|---|---|
| Решение по домену (восстановить старый или купить новый) | Без домена сайт живёт на адресе GitHub Pages | **27.10.2026** |
| Оплата хостинга и выдача секретов в GitHub | Автодеплой на российский хостинг | До релиза |
| Удаление старого Cloudflare Worker | Отдаёт недостоверные расчёты | Сразу после Milestone 1 |
| Выбор лицензии репозитория | Публичный репозиторий без правил использования | До релиза |
| Данные рекламодателя и токен erid, либо решение не показывать баннеры | Требование ст. 18.1 ФЗ «О рекламе» | До монетизации |
| Запрос реквизитов и ставок у компаний | Требование ст. 28 ФЗ «О рекламе»; 4 компании без ставок | Milestone 3 |

Пока ответа нет, работа не останавливается: выбирается самый безопасный вариант
(сайт на адресе GitHub Pages, деплой выключен до появления секретов, баннеры выключены),
и это зафиксировано в `docs/DECISIONS.md`.
